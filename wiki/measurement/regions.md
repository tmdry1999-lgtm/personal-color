# 측정 부위

## 왜 여러 부위인가
- 퍼스널컬러는 피부·머리카락·눈동자의 조합으로 정의된다.
- Lumina 연구: 눈과 머리카락 특징이 피부만보다 정보량이 크다.
- 국내 퍼지 진단 특허: 피부 > 머리카락 > 눈동자 순으로 가중치를 둔다.
- 대비 축은 머리카락·눈 없이 계산할 수 없다.

## 부위 표 (스펙 6.3)

| 부위 | 위치 찾기 | 쓰는 축 | 제외 조건 |
|---|---|---|---|
| 피부 (양 볼, 이마, 턱) | MediaPipe 얼굴 점 | 웜/쿨, 명도, 채도 (주 근거) | 각 영역 L* 상하위 10% 픽셀 제거 |
| 눈동자 | 홍채 점 10개 | 대비, 웜/쿨 보조 | 눈 감음, 안경 반사 감지 |
| 머리카락 | MediaPipe 멀티클래스 분리 (클래스 1) | 대비, 명도 보조 | "염색" 체크 또는 채도가 설정값 초과 |
| 입술 | 입술 윤곽 점 | 웜/쿨 보조 | "립 제품" 체크 또는 채도가 설정값 초과 |
| 눈썹 | 눈썹 점 | 대비 보조 (낮은 가중치) | 없음 |
| 목 — 빛 받은 부분만 (3단계-A 추가) | 위 두 목 영역에서 밝기 하위 50%(그림자)·상위 10%(반사광)를 버린 값 (`neckLit`, `liftedNeckLit`) | 기록만. 그림자 영향 비교용. 기존 목 값은 그대로 | 위와 같음 |
| 목 — 턱 든 사진 (3단계-A 추가) | 운영자가 **턱 들기 모드**를 켰고 베이스 화장 체크 시에만: 얼굴 촬영 직후 "턱을 살짝 들어 주세요" → 얼굴 촬영 때보다 `neckLiftMinDeg`(12°) 이상 든 상태가 1초 유지되면 10장 더 촬영 → 같은 방식으로 목 영역 측정 (`liftedNeck`). `neckTimeoutSeconds`(10초) 안에 못 들면 건너뛰고 경고 `neck_not_lifted`. 턱 들기 모드는 기본 꺼짐(2026-10-15): 판정에 아직 안 쓰는 값이라 방문객 대기를 늘리지 않기 위함 | **아직 판정에 안 씀.** 턱 그림자(간접광) 없이 목 색상각을 얻기 위함. 얼굴 사진의 목(`neck`)과 비교용으로 둘 다 기록 | 목 사진의 A4 실패·목 없음 → 경고 `neck_failed:*`, 얼굴 결과는 그대로 |
| 목 (3단계-A 추가) | 멀티클래스 분리의 몸 피부(클래스 2) 중 턱 끝(152번 점) 아래, 얼굴 폭 안, 얼굴 폭의 0.4배 높이까지 | **아직 판정에 안 씀.** 색상각·b*·채도를 기록해, 화장한 얼굴 대신 웜/쿨을 가를 수 있는지 데이터로 확인 | 마스크 없음 |

설정값(채도 기준 등)은 [임계값](../scoring/thresholds.md)에 있다.

## 이상치 제거
- 각 영역에서 L* 기준 상위 10%(반사광)와 하위 10%(그림자) 픽셀을 버린다.

## 촬영 조건
| 조건 | 기준 |
|---|---|
| 얼굴 수 | 정확히 1개 |
| 얼굴 크기 | 얼굴 폭 ≥ 화면 폭의 25% |
| 고개 회전 | ≤ 15° |
| 유지 시간 | 조건이 3초 유지되면 촬영 |
| 촬영 | 1초 동안 10장, 부위별 측정값은 10장의 **중앙값** |

## 흰자 교차 확인
- 눈 흰자는 거의 무채색이다. A4 보정 후 흰자의 C*가 12를 넘으면 보정이 의심스럽다는 뜻이다.
- MVP에서는 운영자 화면에 경고만 남기고 결과는 막지 않는다.

## 자기 신고 체크
- "염색했어요" → 머리카락을 모든 축 계산에서 제외 (대비는 눈동자·눈썹으로 계산)
- "립 제품을 발랐어요" → 입술 제외
- "베이스 화장(파운데이션·쿠션)을 했어요" → 지금은 기록만 한다. 목 피부 데이터가 모이면 웜/쿨 판정에 쓸지 정한다
- 눈동자 색상각이 `irisMaxHueDeg`(90°)를 넘으면 안경 반사로 보고 눈동자 제외 (`iris:auto`). 시작·촬영 화면에 "안경은 잠시 벗어 주세요" 안내
- 제외된 부위의 가중치는 같은 축의 남은 부위에 비례 배분한다([축 계산식](../scoring/axis-formulas.md)).
- 체크하지 않아도 채도 기준으로 자동 감지해 제외한다.
