# 웹캠 퍼스널컬러 진단 부스 — 설계 스펙

- 작성일: 2026-10-12
- 상태: 검토 대기
- 다음 단계: 이 스펙 승인 → 1단계(위키) 구현 계획 작성

---

## 1. 목적과 성공 기준

### 목적
디지털 AI 부스에서 관람객이 웹캠 앞에 서면 1~3분 안에 퍼스널컬러 진단 결과를 받고, QR로 결과를 폰에 가져가는 교육용 무료 체험 서비스.

### 목표 수준 (현실적인 기준)
- 전문가 라벨 5,000장으로 학습한 딥러닝도 4계절 정확도가 약 70%였다. 웹캠 + 규칙 기반 방식에 그 이상의 정확도를 약속하지 않는다.
- 대신 다음 두 가지를 목표로 한다.
  1. **일관성**: 같은 사람은 같은 조건에서 늘 같은 결과 (반복성 5회 중 4회 이상 동일 계절)
  2. **정직함**: 1·2위 계절이 가까우면 "경계형"으로 표시하고, 결과에 "참고용" 문구를 넣는다.

### 제약
- 예산 최소: 웹캠, 기존 PC, 흰색 A4 용지, 무료 호스팅만 사용
- 사진과 개인정보는 어디에도 저장하지 않는다.
- 학습용 정답 데이터가 없다 → 기준값은 논문·이론에서 가져온 가설로 시작한다.

## 3. 진행 단계

각 단계는 시작 전에 구현 계획을 승인받고, 계획에 있는 것만 만든다.

| 단계 | 내용 | 산출물 |
|---|---|---|
| 1 | 위키 핵심 문서 | `CLAUDE.md`, `raw/`, `wiki/` (5장 참고), 대표값과 팔레트 초안 |
| 2 | **MVP**: 처음부터 끝까지 동작하는 뼈대 | 대기 → 시작 → 촬영 → 판정 → 결과(디자인 없음) → QR |
| 3 | 정확도 다듬기 | 반복성·조명·안정성 테스트, 기준값 조정 |
| 4 | 결과 항목 채우기 | 가상 드레이핑, 4축 근거 그래프, 메이크업/상의/안경테/금속, QR 페이지 헤어·키워드 |
| 5 | 디자인 | 부스 화면과 QR 페이지 시각 디자인 |

**설계 중 정리한 점:** 12톤 계산은 4축 점수가 있으면 추가 비용이 거의 없어서 MVP(2단계)에 포함한다. 3단계는 새 기능이 아니라 기준값 조정에 집중한다.

```

├─ raw/               # 원본 자료. 넣은 뒤 수정 금지
│  ├─ papers/         #   논문 초록, 특허 요약
│  └─ web/            #   웹 자료 요약 + 출처 URL
└─ wiki/
   ├─ index.md        #   전체 목차 (한 줄 요약 + 링크)
   ├─ log.md          #   추가·수정 기록
   ├─ theory/         #   4축 정의, 4계절과 12톤 도출 규칙, PCCS 톤 체계
   ├─ measurement/    #   조명 조건, A4 보정, 흰자 교차 확인, 부위별 측정법, Lab 변환
   ├─ scoring/        #   축 계산식, 계절·톤 대표값, 가중치, 기준값의 근거
   ├─ palettes/       #   12톤별 베스트/워스트, 메이크업, 상의, 안경테, 금속, 헤어, 키워드
   └─ decisions/      #   결정 기록 (2장 표 + 검토했지만 쓰지 않은 자원과 이유)
```

### 운영 규칙 (CLAUDE.md에 기록)
1. **추가**: 새 자료는 `raw/`에 넣고, 관련 위키 문서를 갱신하고, `log.md`에 기록한다.
2. **질문**: `index.md`부터 읽고, 답할 때 근거 문서를 링크한다.
3. **점검**: 문서 간 모순, 출처 없는 숫자를 주기적으로 확인한다.

### 위키와 앱 데이터의 관계
- `wiki/scoring/`의 대표값·가중치 → `app/data/seasons.json`
- `wiki/palettes/`의 색상 → `app/data/palettes.json`
- 위키가 원본이다. 위키를 고치면 JSON도 함께 갱신하고, JSON 각 항목에 근거 위키 문서 경로를 남긴다.

## 6. 진단 알고리즘

모든 숫자 기준값(임계값, 가중치, 대표값)은 **가설**이며 `seasons.json`에 둔다. 아래에 적힌 숫자는 초기값이다.

### 6.1 촬영
1. 얼굴 조건 확인: 얼굴 1개, 얼굴 폭이 화면 폭의 25% 이상, 고개 회전 15도 이하
2. 조건이 3초 유지되면 1초 동안 10장 촬영
3. 부위별 측정값은 10장의 중앙값을 쓴다.

### 6.2 색 보정
1. **A4 보정**: 운영자가 지정한 A4 영역의 평균 RGB(선형값)로 채널별 배율을 구해, A4가 기준 흰색이 되도록 전체 색을 보정한다(화이트밸런스 + 노출). 기준 카드 종류(흰색/18% 회색)와 목표값은 설정값이다.
2. **흰자 교차 확인**: 보정 후 눈 흰자의 채도(C*)가 설정값을 넘으면 운영자 화면에 경고를 남긴다. MVP에서는 결과를 막지 않는다.

### 6.3 부위별 측정

| 부위 | 위치 찾기 | 쓰는 축 | 제외 조건 |
|---|---|---|---|
| 피부 (양 볼, 이마, 턱) | MediaPipe 얼굴 점 | 웜/쿨, 명도, 채도 (주 근거) | 각 영역 L* 상하위 10% 픽셀 제거 |
| 눈동자 | 홍채 점 10개 | 대비, 웜/쿨 보조 | 눈 감음, 안경 반사 감지 |
| 머리카락 | MediaPipe 멀티클래스 분리(머리카락 클래스) | 대비, 명도 보조 | "염색" 체크 또는 채도가 설정값 초과 |
| 입술 | 입술 윤곽 점 | 웜/쿨 보조 | "립 제품" 체크 또는 채도가 설정값 초과 |
| 눈썹 | 눈썹 점 | 대비 보조 (낮은 가중치) | 없음 |

각 부위는 Lab(L*, a*, b*), C*, 색상각 h°로 변환한다. 색 변환은 culori 라이브러리를 쓴다.

### 6.4 4축 점수
각 축은 0~100 점수로 만든다. 제외된 부위의 가중치는 남은 부위에 비례 배분한다.

| 축 | 계산 근거 |
|---|---|
| 웜/쿨 | 피부 b*·h° (주) + 입술 h°, 눈동자 h° (보조) |
| 명도 (라이트/딥) | 피부 L* (주, ITA 구간 참고) + 머리카락 L* (보조) |
| 채도 (브라이트/소프트) | 피부 C* (주) |
| 대비 | 피부 L*와 머리카락·눈동자·눈썹 L*의 차이를 가중 평균 (눈썹은 낮은 가중치, 6.3) |

### 6.5 판정
1. **4계절**: 4축 점수와 각 계절 대표값 사이의 가중 거리를 구하고, 거리의 역수 비율로 %를 만든다(국내 퍼지 진단 특허와 같은 방식).
2. **12톤**: 판정된 계절 안에서 대표값 대비 가장 두드러진 축으로 고른다.
   - 봄: 라이트 / 브라이트 / 트루(웜)
   - 여름: 라이트 / 소프트 / 트루(쿨)
   - 가을: 소프트 / 딥 / 트루(웜)
   - 겨울: 브라이트 / 딥 / 트루(쿨)
3. **경계형**: 1위와 2위의 차이가 10%p 미만이면 "여름-겨울 경계형"처럼 함께 표시한다.

### 6.6 실패 처리
다음 경우 결과를 내지 않고 안내 문구와 함께 다시 촬영한다.
- 얼굴이 없거나 2명 이상
- A4 영역이 가려짐(영역 내 편차 큼) 또는 하얗게 날아감(채널 값 포화)
- 보정 전 피부 L*가 설정값 미만(너무 어두움)

## 7. 화면 흐름

### 7.1 부스 화면
| # | 화면 | 내용 | 단계 |
|---|---|---|---|
| 1 | 대기 | 웹캠 미리보기(거울), 제목, [시작] | MVP |
| 2 | 시작 | [여성]/[남성], ☐ 염색했어요, ☐ 립 제품을 발랐어요, 사진 미저장 안내, [진단 시작] | MVP |
| 3 | 촬영 | 얼굴 가이드, 실시간 안내("조금 더 가까이" 등), 자동 3초 카운트다운 | MVP |
| 4 | 분석 중 | "피부 · 눈동자 · 머리카락 분석 중…" (1~2초) | MVP |
| 5 | 결과 | 아래 표 | MVP + 4단계 |

결과 화면 구성:

| 영역 | 내용 | MVP | 4단계에서 추가 |
|---|---|---|---|
| 판정 | 4계절 + %, 12톤(참고), 경계형 | ✅ | |
| 근거 | 4축 | 숫자 | 그래프 + 피부색 칩 |
| 드레이핑 | 실시간 얼굴 주변 색 테두리, 베스트/워스트 전환 | | ✅ |
| 추천 색 | 베스트, 워스트 | ✅ | 메이크업(여) / 상의·안경테(남), 금속 |
| QR | QR + "사진 등의 개인정보는 저장되지 않습니다" + "참고용 결과예요" | ✅ | |
| 버튼 | [처음으로], 60초 무조작 시 대기 화면 복귀 | ✅ | |

### 7.2 QR 결과 페이지 (폰)
- 부스 결과 화면의 내용을 세로 배치로 표시 (사진 없음)
- 드레이핑 대신 베스트/워스트 큰 색 칩
- QR 전용: 헤어 컬러 추천, 톤 키워드 (4단계)

### 7.3 운영자 설정 화면
- 단축키 Ctrl+Shift+S로 열기
- 웹캠 선택, A4 영역 지정(마우스 드래그, 브라우저에 저장), 측정 원본값 보기(반복성 테스트용), 경고 기록 보기

### 7.4 QR URL 형식
```
https://<계정>.github.io/<저장소>/result.html?v=1&g=f&s=summer&t=summer-light&p=21,62,9,8&x=38,71,30,55&b=winter
```
| 키 | 의미 |
|---|---|
| v | 형식 버전 |
| g | 성별 (f/m) |
| s | 판정 계절 |
| t | 12톤 |
| p | 봄·여름·가을·겨울 % |
| x | 4축 점수 (웜/쿨, 명도, 채도, 대비) |
| b | 경계형일 때 2위 계절 (없으면 생략) |

사진, 얼굴 좌표, 원본 색값은 넣지 않는다. 팔레트 등 표시 내용은 결과 페이지가 `palettes.json`에서 가져온다.

## 8. 코드 구조

- 빌드 도구 없이 HTML + ES 모듈
- CDN 라이브러리: MediaPipe Tasks Vision(얼굴 점, 멀티클래스 분리), culori(색 변환·CIEDE2000), QR 생성 라이브러리
- 테스트: Node 내장 테스트 도구 (`node --test`), 이 PC의 Node 24 사용

```
app/
├─ index.html            # 부스 앱
├─ result.html           # QR 결과 페이지
├─ src/
│  ├─ camera.js          # 웹캠 열기, 10장 촬영
│  ├─ face.js            # MediaPipe → 부위별 픽셀
│  ├─ calibrate.js       # A4 보정, 흰자 교차 확인
│  ├─ measure.js         # 부위별 Lab 측정, 이상치 제거
│  ├─ axes.js            # 4축 점수
│  ├─ classify.js        # 4계절 %, 12톤, 경계형
│  ├─ result-code.js     # 결과 ↔ URL
│  └─ screens/           # 화면 5개 + 운영자 설정
├─ data/
│  ├─ seasons.json       # 대표값, 가중치, 임계값 (위키 scoring/ 기반)
│  └─ palettes.json      # 팔레트 (위키 palettes/ 기반)
└─ tests/
```

**원칙:** `calibrate → measure → axes → classify → result-code`는 카메라·화면 없이 숫자를 받아 숫자를 돌려주는 순수 함수로 만든다. 웹캠 없이 테스트할 수 있다.

**배포:** GitHub Pages(공개 저장소). 부스 PC는 Chrome 키오스크 모드로 같은 주소를 연다. 웹캠은 https에서만 켜지며 GitHub Pages가 이를 충족한다.

## 9. 테스트와 현장 점검

### 9.1 자동 테스트 (Node)
1. 색 변환: 정답이 알려진 값 (예: sRGB 흰색 → L* = 100)
2. A4 보정: 색이 치우친 A4 입력 → 보정 후 무채색
3. 판정: 각 계절 대표값 → 해당 계절, 중간값 → 경계형
4. QR URL: 결과 → URL → 결과 왕복 시 값 동일
5. 팔레트 데이터: 12톤 모두 존재, 색 코드 형식 유효

### 9.2 반복성 테스트 (웹캠, 사람이 진행)
- 같은 사람 5회 촬영 → 4회 이상 같은 계절이면 합격

### 9.3 조명 변화 테스트 (웹캠, 사람이 진행)
- 따뜻한 조명/차가운 조명에서 촬영 → A4 보정을 켰을 때 계절이 바뀌지 않아야 한다

### 9.4 안정성 테스트
- FairFace 동아시아인 사진 약 100장 → 오류 없이 처리되고, 한 계절에 90% 이상 몰리지 않아야 한다
- 정답이 없으므로 정확도 평가가 아니다

### 9.5 현장 점검표
1. 조명 5000~5500K, 연색성(CRI) 90 이상, 얼굴 정면
2. A4 배경판 고정 + 운영자 화면에서 위치 지정
3. 웹캠 고정, Chrome 키오스크 모드, 인터넷 연결
4. QR을 아이폰·안드로이드로 열어보기
5. 60초 자동 복귀, PC에 사진 파일이 생기지 않았는지 확인

### 9.6 MVP 완료 기준
- 대기 → 결과 → QR까지 끊김 없이 동작
- 자동 테스트 전부 통과
- 반복성 테스트 4/5 이상
